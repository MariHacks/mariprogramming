# MariTools surface brief

- **Scope:** All routes under `/tools` — home, schedule, free time, semester, catalog, clubs, forum (list + thread), and account (header entry only; page lives in tools shell).
- **Visitor mode:** Operate — students complete campus tasks quickly with scanability and familiar affordances.
- **Audience:** Marianopolis students using Omnivox schedules, course outlines, club listings, and course-tagged forum threads.
- **Independence:** MariTools is not Book Delivery. No cart, no book commerce, no `/books` chrome. Catalog book rows are reference data only.
- **Primary tasks:** Paste schedule → calendar; compare free time; upload outline → review → optional catalog contribute; browse catalog/clubs/forum; sign in for private saves and posts.
- **Constraints:** No user-facing term picker in tools chrome (term resolves automatically). Account in site header, not sidebar. No “Programming Club initiative” strip in tools chrome. No term/date invention. Reduced motion complete.
- **Chosen direction:** Campus Lab Manual — Student Technical Journal shifted into Operate density: ruled tables, instrument sidebar, mono for codes and times.
- **Memorable moment:** Schedule week grid reads like a printed registrar timetable; sidebar feels like a lab manual table of contents.
- **Motion:** 120–220ms state feedback; no decorative page-load choreography.
- **Full spec:** `.impeccable/briefs/maritools-redesign-spec.md` (Arena-synthesized Campus Lab Manual).
